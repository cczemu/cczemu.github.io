### 初次搭建

2021年11月7日，在看到[ManateeLazyCat](https://manateelazycat.github.io/index.html)的博客感到美观与优雅，看他的「[我人生的前28年](https://manateelazycat.github.io/life/2016/03/03/my-life-before-28-years.html)」内心五味陈杂，看到ArchLinux中文社区的小伙伴都拥有自己的博客，于是便萌生了搭建博客的想法，看到他博客结构简单，于是我想不用现成的工具去搭建博客，以前有用过Hexo、WordPress等框架，但是我更想“简单”，于是手写网页，花了一两天吧，其实是很久没写关于前端的东西了，所以便有些生疏，目前还有一些功能还没实现，一步步来吧，我是目前打算把她搭建到Github Pages的，我想在她上面分享一些人生感悟，还有我想记录的东西，总之先这样吧！

### Python静态渲染

2022年2月7日，搁置好久的博客突然想写了一些，原本md->html的工作由Typora完成，后来Typora收费了，今天实现了用pandoc处理md->html的方法，撰写日期目前不打算实现，因为原本的撰写日期的代码是运行article.py文件的时间，现在程序被我写成，会遍历所有文件夹下的md文档并生成html，所以撰写时间就成了生成时间。

2月9日上午，适配了小型设备的布局问题，目前还需解决文章渲染器杂乱无章，完成标签渲染器！快要完成啦！😉开心！

2月9日中午，重写文章渲染器成功，每一篇文章的日期为最后一次修改时间，首页并进行修改时间排序，最新更新的文章会放在第一列，完善了首页渲染器，加入总文章数和总字数。

2月9日晚上，Tags渲染器写完了，用了一些侵淫巧计，是因为Python不太会，不过功能确实是实现了，这样博客程序算是告别了一个段落。

### AJAX / Fetch API

这个博客的第一个版本也就是2022年是用Python写的渲染器。而2023年就用了AJAX重写了，也是一个版本，AJAX版本Markdown解析就用上了Marked.js，而且每个Markdowm文件都加上YAML，
这样的话每个Markdowm文件内置了标签，撰写时间，就不需要用例如NodeJS OS模块去获取文件创建时间或者修改时间，因为这样就违背了纯前端博客的设想。

如今2024年用Fetch API重写了一边，之前解析YMAL的function被我换成了一个现成的库叫grayMatterBrowser，感觉还有些性能问题待解决。

### 从最初版本到现在的改进

> 以下内容由 GitHub Copilot 根据根目录项目当前代码和 Git 历史整理撰写，不属于原始文章内容。

这里对比的是根目录的新版项目，不包括 `v1` 目录中的旧版博客。

最初的根目录版本仍然保留着较多静态站点和旧版构建工具的痕迹：首页、文章页和标签页各自维护页面逻辑，文章内容主要依赖额外的生成流程，页面之间的代码也比较分散。后来项目逐渐转向纯前端博客：浏览器直接读取 `links.json`，再通过 `fetch` 加载 `posts/` 目录中的 Markdown 文件，并在客户端完成解析和渲染。这样发布文章时不需要重新生成整站页面，更符合 GitHub Pages 静态部署和“简单”的初衷。

文章数据格式也变得更完整。每篇 Markdown 文件现在可以通过 YAML Front Matter 保存标题、分类和日期，首页可以据此生成文章标题、摘要、字数、日期和标签，标签页也能自动整理文章分类，文章详情页则复用同一份元数据。这比早期依赖文件名或生成时间的方式更稳定，也让文章内容和文章展示信息保持在同一个文件中。

页面结构从单一的文章列表扩展成了首页、标签页和独立文章页。导航在桌面端和移动端都有对应布局，移动端可以展开菜单；文章详情页支持 Markdown 表格、代码块、图片以及外部链接，新页面还增加了外链安全属性。页面加载失败时也会显示提示，而不是让页面停留在空白状态。

视觉部分从旧版的简单样式逐渐发展为三套可切换主题：Liquid Glass、Material Design 1 和 Material Design 3 Expressive。主题、壁纸和透明度设置会保存在浏览器的 `localStorage` 中，用户刷新页面后仍能保留选择。背景图片也统一为水平垂直居中、按比例覆盖视口且不重复，首页、标签页和文章页使用同一套背景规则。

最近一次改进集中在代码组织。以前首页、标签页和文章详情页分别重复编写文章列表及 Markdown 文件的请求逻辑，现在新增了 `script/posts.js`，统一负责文章列表读取、文章请求和 front matter 解析；`script/content.js` 专注于 Markdown 解析、清理和纯文本提取，页面脚本则只负责自己的 DOM 展示。这样以后修改文章加载方式时只需要维护一个模块，也降低了三个页面行为不一致的可能。

目前项目仍然是无构建步骤的静态前端，优点是部署简单、依赖少，缺点是部分依赖通过 CDN 加载，文章较多时首页和标签页会同时请求多个 Markdown 文件。后续可以考虑增加缓存、分页或搜索功能，并进一步拆分公共样式和主题样式；不过现阶段的结构已经比最初版本更清晰，也更容易继续扩展。
