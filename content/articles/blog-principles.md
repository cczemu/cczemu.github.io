这篇文章用简单的方式介绍这个博客是怎样工作的。它没有依赖服务器程序来生成每一篇文章，而是把网页、JavaScript 和 Markdown 文件作为静态文件发布，浏览器负责把它们组合起来。

### 1. 静态文件托管

博客的 HTML、CSS、JavaScript、图片和文章都放在仓库中。GitHub Pages 发布这些文件后，访问者的浏览器就可以直接下载它们。服务器不需要为每次访问运行博客程序，也不需要数据库。

这让部署和维护比较简单；代价是文章列表等内容需要由浏览器加载和整理。

### 2. 文章内容与索引

文章保存在 `content/articles/` 目录下，每篇文章都是 Markdown 文件。文件开头的 YAML Front Matter 用来保存标题、分类和日期，例如：

```yaml
---
title: 一篇新文章
categories: Web
date: 2026-10-19
---
```

`data/articles.json` 保存文章文件名列表。首页和标签页先读取这个索引，再用 Fetch API 加载相应的 Markdown 文件。新增文章时，除了创建 Markdown 文件，也要把文件名加入索引。

### 3. 浏览器解析和显示

浏览器获取文章后，gray-matter-browser 读取 Front Matter 和正文，Marked.js 将 Markdown 正文转换为 HTML。首页从文章内容生成摘要、字数和日期，文章详情页则显示完整正文，标签页按分类整理文章。

转换得到的 HTML 会先经过 DOMPurify 清理，再放进页面。这样可以降低 Markdown 中不可信 HTML 带来的风险。获取文章或索引失败时，页面也会显示加载失败提示。

### 4. 为什么这样设计

文章用 Markdown 撰写，容易阅读，也方便用 Git 管理修改历史。静态托管没有后端服务需要维护，浏览器端解析则让新增文章不必重新生成整站。

这个方案适合内容规模不大、希望保持简单的个人博客。如果文章数量很多，访问时逐篇请求可能变慢；届时可以再考虑生成构建索引、缓存或迁移到静态站点生成器。
